# Dashboard UI

- Use React and official shadcn/ui components for every UI element covered by the registry. Check src/components/ui first and reuse the existing component.
- When a component is missing, add the matching New York shadcn/ui registry component and only the dependencies the feature needs.
- Compose Field, Input Group, Dialog, Card, and other primitives before creating equivalents with HTML and Tailwind utilities.
- Use the registry component for its intended interaction. Use Switch for on/off preferences, Toggle for pressed actions, and ToggleGroup for related pressed actions. Keep the registry markup and styles as the baseline. Apply project-specific layout, RTL, and Tokyo Night styling through composition, shared tokens, and targeted styles.
- Use semantic HTML for page landmarks and CSS for decorative artwork. Add components only when the feature calls for them.

## Design language

Use the login screen for branded entry flows. Inside the dashboard, follow the RTL workspace layout used by Settings. Place primary navigation on the right, contextual navigation immediately beside it, and the page heading above the content. Group related settings in lightly bordered shadcn Cards with separated rows and logically aligned controls. Use the dashboard surface and radius tokens in src/theme.css for workspace screens and their overlays. At narrow widths, stack contextual navigation and controls in reading order. Share interaction patterns across the product.

- **Theme.** Import the shared tokens from src/theme.css through the app stylesheet. Use semantic colors for page backgrounds, card surfaces, text, borders, dividers, focus rings, and errors. Keep Tokyo Night as the default dark theme and support the light theme with the same tokens. Respect the user's stored theme choice.
- **Brand and surfaces.** Keep Zilber's monochrome logo and neon purple-to-dark gradient for branded surfaces. Use subtle borders, restrained shadows, and a glass surface over decorative gradients where the text remains readable. Standard content remains on semantic card surfaces. The login frame is 900 px wide and at least 560 px tall on desktop, with a 7:5 split and a stacked mobile layout. Treat those dimensions as the login reference.
- **Shape and spacing.** Reuse the radius tokens in src/theme.css. Cards and the login frame default to 10 px corners. Form controls use a quarter of their height as the corner radius. Logo frames and the recovery dialog use 12 px. Use the 4 px spacing scale, including 8 px between a label and its field. Login fields and the main action are 40 px tall and share a width.
- **Typography and direction.** Use Vazirmatn with Inter as the Latin fallback. Use 24 px/700 for prominent section titles, 13 px/500 for field labels, 14 px for control text, and 12 px for tertiary metadata. Use DirectionProvider for RTL component behavior. Set email and password fields to LTR and isolate company names and version numbers when direction can vary. Display the configured company name within the login heading.
- **Forms.** Prefer Field, FieldLabel, Input, InputGroup, and Button. Keep labels visible above fields, preserve keyboard focus indicators and accessible names for icon controls, and associate invalid fields with their feedback. Keep the icon that reveals a password within its InputGroup. A pending action uses Spinner and disables repeat submission. Add a themed Separator only where it clarifies the boundary between groups.
- **Feedback and motion.** Use src/components/form-feedback.jsx for messages tied to a form. It wraps the shadcn/ui Alert and animates the space the message occupies. Pass tone="success" for successful actions and tone="error" for errors. Keep the message available while open becomes false so the closing animation can finish. In a grid with row gaps, set --form-feedback-gap to that gap. Use the shared motion tokens and respect prefers-reduced-motion.
- **Overlays and preview.** Use shadcn/ui Dialog for a separate task such as password recovery. Keep the appearance panel and simulated outcomes in development. Check idle, loading, success, and error states, as well as keyboard interaction and the light and dark layouts.
